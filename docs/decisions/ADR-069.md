## ADR-069 — Three parallel deep reviews: one crash, one broken language, one broken recall

**Status:** accepted

**Context.** Three `code-reviewer` agents were run in parallel over three
disjoint subsystems -- `core/memory/**`, `core/router/**`, and the Python
under `senses/**` -- each asked for logic defects with a concrete failing
input, not style. All three came back **REQUEST CHANGES** with real,
reproducible findings. Every one was re-verified here against the running
code before being fixed.

The memory findings are in their own commit; this ADR covers the router
and senses work, plus what the whole exercise says.

---

**1. CRITICAL — one malformed line killed the `voice` or `eyes` daemon.**

`senses/ipc.py`'s `read_lines` called `json.loads` unguarded. The
exception surfaces from the *generator's own* `next()`, which happens
**outside** every `try/except` in both callers: `voice/main.py`'s
`for message in ipc.read_lines(conn)` isn't wrapped at all, and
`eyes/main.py`'s `run_forever` only wraps `handle_message`, not the
`for` statement pulling the next line.

Reproduced against the real reader: a valid message, then `this is not
json`, and the reader died -- the *next valid message never arrived*.
So one bad byte on a socket that has no auth beyond file permissions
took down TTS, or the entire camera/gesture/pointer subsystem, until
something restarted it. That breaks SPEC.md § 2's "always on" / "idle"
contract outright.

Fixed in `read_lines` itself: a malformed line (bad JSON or invalid
UTF-8) is logged and skipped, and the stream keeps serving. Verified
live -- the message after the bad one now arrives. 4 new tests, driving
raw bytes through a real socketpair.

---

**2. HIGH — every Portuguese reflex utterance was answered in English.**

`RulesProvider` is the *only* registered `reflex` provider, and every
pattern in it was English-only -- while `laneClassifier.ts`'s own prompt
and `laneHeuristic.ts` both explicitly route PT-PT phrases there
("para", "que horas são", "diz outra vez", "mais alto", "estás aí", "é
tudo", "liga a câmara"). So saying "para" classified as `reflex`
correctly, matched nothing, and fell through to a generic English "Got
it." Every one of the fastest, most frequent things JARVIS says was in
the wrong language, contradicting ADR-039's bilingual work everywhere
else in the stack.

Fixed: each rule now carries both languages, chosen by the utterance's
own language, and the no-rule-fired fallback follows suit ("Certo.").

**A second bug surfaced while testing that fix**, worth recording
because it is the *same* trap as one of the memory findings in the
sibling commit: JavaScript's `\b` is defined in terms of `\w`, which is
ASCII-only, so `/\bé tudo\b/` and `/\bestás aí\b/` **do not match their
own literal text**. Both silently fell through to the fallback even
after the PT patterns were added. Fixed by stripping accents before
matching and writing every pattern unaccented -- which also makes real
STT output match whether or not it carried the accents, which it does
not always do.

---

**3. HIGH — `classifyLane` crashed on valid JSON that isn't an object.**

`JSON.parse("null")` succeeds, and `null.lane` is a `TypeError` thrown
*outside* the `try` that guards the parse -- so it escaped as an
uncaught crash rather than the `LaneClassificationError` this function's
entire contract is built on. Same for a bare number, string, or array.
A weak model in the fallback chain emitting `null` under load is a
plausible trigger, and it would have failed the turn instead of falling
back. Fixed with an explicit non-object guard; 6 new cases.

---

**Recorded, not fixed in this pass** (real, lower impact, each with a
concrete scenario in the review):
- `senses/ears/audio_capture.py` leaks one temp WAV per captured
  utterance, forever -- `mkstemp` with nothing deleting it, on an
  always-on daemon. Directly relevant given this machine's own disk
  pressure earlier this session.
- The rate-limit token is taken *before* the concurrency check and never
  refunded on a concurrency refusal, so bursts silently erode the real
  rpm budget with requests that never left the process.
- Closing the camera while gesture tracking is live can race
  `cap.release()` against a `cap.read()` on the loop thread -- native
  OpenCV, not catchable in Python. The existing test passes
  `spawn=lambda fn: None`, so no real thread ever runs and it can only
  prove the *signal* was sent.
- The Gemini key rides in the URL query string rather than a header,
  unlike every other provider here.

**Consequences.**
- 575 TS (was 569) + 112 Python (was 108), `make check` green.
- The reviews also confirmed real strengths with reasoning, not just
  absence of findings: `routeChat`'s no-interleave/no-fallback-after-
  yield semantics hold on every throw path; UTF-8 multi-byte characters
  split across network chunk boundaries are genuinely handled (verified
  live) in all four stream readers; `ipc.py`'s own byte-level buffering
  and 10MB cap cannot drop a valid message; `session.py`'s idle-vs-cap
  timeout arithmetic matches SPEC.md § 6 exactly; and the
  `POINTER_CONTROL` click-safety property is well covered.
- Worth stating: two of the three subsystems were broken **specifically
  for Portuguese**, in the same ASCII-`\w`/`\b` way, in code written
  months apart. That is a pattern, not two coincidences -- any future
  regex touching user text in this project should be assumed wrong until
  checked against accented input.
