## ADR-063 — Dashboard bugs only a *populated* live dashboard could show

**Status:** accepted

**Context.** Every previous dashboard verification pass (ADR-022, ADR-028,
ADR-054) ran against a dashboard with little or no real data in it. Run
against a real `core` with 13 skills loaded, 5 pending approvals, a real
conversation history and real system metrics, the layout broke in ways an
empty dashboard structurally cannot reveal. Verified with Playwright at
1512, 1280 and 900px, with real screenshots read back and real geometry
measured -- not by reading CSS.

---

**1. Panels rendered on top of each other.** With 5 pending approvals,
the Approval Queue's content painted straight *through* its own border
and over Hand Tracking, Live Data and the Conversation Log below it --
three panels at once, unreadable.

Root cause: `Panel`'s body had **no overflow control at all**, and its
tilt `transform` creates a stacking context, so escaping content paints
over its siblings rather than behind them. A bordered panel whose content
escapes its own border is always a bug.

Fixed structurally: the panel body is now `overflow-hidden flex flex-col`,
with `{children}` wrapped in `flex-1 min-h-0` so a child that sets its own
`overflow-y-auto` gets a bounded height to scroll within instead of
growing past the clip and vanishing. `approval-queue.tsx` also dropped
`lg:max-h-none`, which had disabled its own scroll cap on exactly the
large screens where the overflow was worst.

**2. Skill Health pushed Metrics and Timeline out of the left column.**
With all 13 real skills the list is ~500px tall, and it was wrapped in a
`shrink-0` div with no internal scroll, so the two panels below it were
simply gone. Fixed: the list scrolls inside its own panel (`max-h-64
overflow-y-auto`), and the `shrink-0` wrapper in `page.tsx` is no longer
needed.

**3. Both side columns collapsed to zero height below 1024px.** Measured
at 900px: left column `height: 0`, right column `height: 0`, centre
column 595px -- so the Orb and Thought Stream appeared painted across the
stacked panels. Cause: the padded container is `absolute inset-0` (a
fixed height) with the three columns as flex items; stacked they total
~1673px against a 621px box, so flex shrinks them and `min-h-0` lets them
shrink all the way to zero. Only the centre column had `shrink-0`, which
is why only it survived.

**Confirmed pre-existing, not introduced by this session's own changes** --
checked by stashing this work and re-measuring, rather than assuming
either way. Fixed with `shrink-0 lg:shrink` on both side columns: natural
height below the breakpoint (the container scrolls), normal flex
behaviour above it.

**4. A raw float on screen.** "DISK FREE 22% (49.10000000000002 GB)" --
`diskTotalGB - diskUsedGB` with no rounding. A dashboard reading out 14
decimal places of IEEE-754 noise reads as broken. Now `.toFixed(1)`, and
the numeric rows use `tabular-nums` so digits stop jittering as values
update.

**5. Text was genuinely too small -- the owner had said so twice.**
Measured on the live page: **483 text elements below 10px**, with 7 at
8px and 33 at 9px. 8px is not a readable size for body text on any
display. Every sub-10px size moved up one step across all 15 components
(10→12, 9→11, 8→10, applied largest-first so nothing was bumped twice).
Re-measured after: **0 elements below 10px**, at all three viewport
widths.

**6. Scrollbars were invisible, so scrollable panels looked broken
rather than scrollable.** 2px wide at 30% opacity on a dark background is
effectively nothing, and after the fixes above several panels genuinely
do scroll. Now 6px at 55% (with a hover state and a Firefox
`scrollbar-width`/`scrollbar-color` fallback, which ignores the
`-webkit-` rules entirely) -- still thin and on-theme, but actually the
affordance it was supposed to be.

**7. Wasted layout space.** Measured at 1512px: left 326px (21.6%),
centre **746px (49.3%)**, right 385px (25.5%) -- half the screen was a
480px Orb in a void while both data columns were cramped. Rebalanced to
26% / ~44% / 30%.

**Also fixed:** the header still read "PHASE 7 · DASHBOARD", several
phases stale. Now just "DASHBOARD" -- a label that can't go out of date
again.

**Consequences.**
- `make check` green (517 TS + 108 Python), `next lint` and `next build`
  clean.
- Verified at 1512 / 1280 / 900px: no horizontal overflow, no text below
  10px, zero console errors at any size.
- **Owner-required, and the reason this ADR exists:** all of this was
  invisible until a dashboard with *real* data was looked at. Future
  dashboard verification should populate it first -- an empty dashboard
  is not a tested dashboard.
