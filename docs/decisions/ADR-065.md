## ADR-065 — "Stop" mid-question became the answer, and fired a real green-tier action

**Status:** accepted

**Context.** Found by a dedicated read-only analysis pass over the whole
repo (2026-08-17), not by a failing test -- because every test that
should have caught it declared the case inapplicable.

`core/skills/conversation/ipc.ts`'s `offerUtterance` resolved a pending
`ask()` with **whatever the next utterance was**, unconditionally. So
while `skills/tasks` awaited "What's the task?", the owner saying "stop"
produced a real Reminders.app item titled **"stop"**. `REMINDERS` is
green-tier, so nothing prompted the owner to catch it before it
happened. `skills/launcher` had the identical shape (`open -a stop`).

The reflex lane's own cancel rules (`core/router/laneHeuristic.ts:45`,
`core/router/providers/rules.ts`) never got a chance to fire: a pending
`ask()` short-circuits dispatch entirely in `core/main.ts` *before* any
lane classification runs.

This is `docs/SKILLS.md` § 7's case 5 (`cancel()` mid-interaction).
`SkillContext.cancel` is declared in `core/skills/types.ts` and **no
skill implements it and nothing calls it**. Six skills that genuinely
call `ctx.ask` -- `tasks`, `launcher`, `media`, `clipboard`, `weather`,
`shopping_list` -- each declared case 5 "N/A, single-turn" in their own
test file. They are not single-turn; the claim was wrong, not the case.

**Decision.** Cancellation is recognised in the conversation layer,
where the pending question actually lives, rather than by asking every
skill to implement `cancel()`:

- New `core/skills/conversation/cancel.ts`: `isCancelUtterance()`
  (bilingual, anchored whole-utterance after normalization -- same
  discipline as `core/skills/socialUtterance.ts`) and `AskCancelledError`.
- `offerUtterance` still *consumes* a cancellation (returns `true`, so
  `core/main.ts` does not also dispatch it as a fresh utterance) but
  **rejects** the pending `ask()` instead of resolving it.
- `core/main.ts` catches `AskCancelledError` specifically and says
  "Cancelled.", recording it as a normal response. A cancellation is not
  a failure, and reporting it as "Something went wrong" -- or logging it
  to the dashboard's error panel -- would be its own small dishonesty
  (CLAUDE.md § 6).

**The false-positive direction is the expensive one** and the tests are
built around it: "stop" cancels, but "stop the timer at six" is still a
real answer, and `para de seguir as minhas mãos` (a real
`look.stop_gestures` utterance) is not a cancellation. The pattern list
is deliberately short for that reason -- a false positive throws away
something the owner just said.

**Consequences.**
- 547 TS tests (was 539) + 108 Python, `make check` green.
- **Not done here:** the six skills' test files still claim case 5 is
  "N/A, single-turn". The behaviour is now correct regardless of what
  those comments say, but the comments are wrong and should be corrected
  when each skill is next touched.
- **Also still open, same analysis pass:** an utterance consumed as an
  answer to `ask()` returns from `core/main.ts` before `memory.appendEvent`
  and the transcript broadcast, so every answer the owner gives to a
  skill's question is absent from both memory and the dashboard
  transcript. Real, separate, not fixed in this ADR.
