## ADR-054 — Dashboard visual refresh: real depth, real data, responsive

**Status:** accepted

**Context.** Owner's request (2026-08-12): more creative and intuitive,
3D effects, responsive, the conversation log taking less space, text more
visible, more widgets, and animations that show JARVIS actually working.
`ROADMAP.md`'s Phase 7 section already pointed at the owner's own Figma
reference as the layout source; `PROGRESS.md` logged that only
palette/typography/panel-style/Orb-math were ever reconciled from it, not
layout — so this closes a previously-recorded gap rather than inventing a
new direction.

**Decisions.**

- **CSS-only 3D, no new dependency.** Confirmed `ui/package.json` has no
  animation or 3D library at all. Deliberately kept it that way: a full
  3D engine (Three.js/react-three-fiber) is real, permanent maintenance
  surface for one maintainer, and everything asked for here is reachable
  with `perspective` + `rotateX/rotateY` + `preserve-3d`. Panels tilt
  toward the cursor (max 4°, small on purpose — a big angle makes 10px
  text genuinely harder to read on an information-dense display) with a
  glow that follows the tilt. The Orb's seven rings now sit at different
  `translateZ` depths, so it reads as a sphere rather than a flat target.
- **The "working" animation is tied to real state, not decorative.** A
  sweeping conic-gradient highlight renders *only* while `orbState ===
  "thinking"` — i.e. while a real dispatch is genuinely in flight. Idle
  looks different from working because the system is different, not
  because something is always spinning.
- **The audio waveform is driven by real microphone RMS.** The Figma
  reference's version used `Math.random()`. This one rides
  `ContinuousAudioSource.add_frame_listener` — the same extension point
  the wake-word scorer already uses, so the hot audio path
  (`_process_frame`) is untouched — computing real per-frame RMS and
  emitting a throttled `audio.level` event (~10/s; frames arrive ~12.5/s
  and nobody perceives a level meter faster than that). Log-scaled, since
  linear RMS makes normal speech look almost flat.
- **Transcript capped, not stretched.** It was the only growable element
  in the narrowest column, absorbing everything left over. Now
  `max-h-44` with tighter line spacing and 8-10px text bumped to 9-11px.
- **Responsive via a real breakpoint, verified at two viewports.**
  Below `lg`, the three columns stack to one scrollable column. Four real
  layout bugs only visible in a rendered browser were found and fixed
  this way, not by reading the code: panels collapsing below their
  content (`min-h-0` is correct inside a fixed-height column, wrong when
  stacked), `flex-1` fighting a stacked column, a `maxHeight: "32%"`
  resolving against no height, and the Orb's label sitting a half-box
  away from it.
- Fixed a pre-existing unrelated bug found on the way: `--font-mono`
  pointed at `var(--font-geist-mono)`, which nothing in this project
  defines — so the `font-mono` utility on `<html>` silently fell back to
  a browser default instead of the JetBrains Mono actually loaded.

**Consequences.**
- `ui/src/components/panel.tsx` (tilt), `orb.tsx` (480px/7 rings/depth/
  sweep), `audio-waveform.tsx` (new), `transcript.tsx`, `app/page.tsx`
  (responsive), `app/globals.css`; `senses/ears/audio_level.py` (new),
  `core/main.ts` relay, both type mirrors.
- 7 new Python tests (74 total), 488 TS tests, `make check` green.
- **Verified in a real browser at 1600px and 900px** (Playwright,
  matching CLAUDE.md § 1's Phase-7-onward rule): measured real column
  widths (345/408px side-by-side → 868/868px stacked), real Orb size,
  and confirmed no page errors. One real bug found by *test design*
  rather than review: the level listener's `0.0` throttle sentinel
  silently swallowed the very first frame against a monotonic clock
  starting near zero.
- **Owner-required:** whether the tilt and the bigger Orb actually feel
  good is a taste call only the owner can make.
